# tsumugi-reminder

一个桌面提醒应用：待办事项、提醒时间、提醒间隔，退出时可选择留在后台，
用桌面桌宠继续提醒。

## 跑起来

```bash
npm start        # 正常运行
npm run dev      # 带开发者工具 + 远程调试端口 9222
npm test         # 跑调度器 / 持久化 / 提示音的单元测试（不需要起界面）
```

数据存在 `%APPDATA%\Reminder\` 下：`data.json` 是全部状态，
`sounds\` 放用户添加的提示音。

## 三张素材的处理

| 文件 | 用途 | 处理 |
|---|---|---|
| `背景图2.jpg` | 进入界面（内置） | 直接用，CSS 用 `cover` 铺满 |
| `背景图1.jpg` | 主界面（内置） | 同上 |
| `替换图1.jpg` | 主界面（内置备选） | 同上。构图和背景图1 同款，可在设置里一键切换 |
| `人物立绘.jpg` | 桌宠（内置） | **重新抠图** → `pet.png` |

这三张背景图都可以在设置里被替换成任意本地图片，详见下面「自定义图片」。

立绘那张是 JPG，原本的透明底被烧成了 32px 的灰白棋盘格压在像素里。
不能简单地「接近白就透明」—— 角色的水手领、皮肤高光、浅蓝裙摆同样接近
白色，会被一起打穿。`tools/cutout.js` 用的是**边缘连通域**判定：只有和
画布四边连通、且呈灰阶高亮的像素才算背景。角色内部的白是封闭区域，够不到
边缘，因此天然免疫。跑 `npm run cutout` 可重新生成。

托盘图标 `tray.png` 是从立绘头部裁出来缩到 64×64 的。

## 自定义图片

设置 → 外观，可以替换**进入界面图 / 主界面背景 / 桌宠立绘**，并调节桌宠大小。

用户选的图会**复制**进 `%APPDATA%\Reminder\images\`（和提示音同样的理由：只记原路径的话，
源文件一挪走界面就白了）。每一项都有「恢复默认」的入口 —— 直接在下拉里选回内置图即可。

**桌宠立绘会自动抠图**，因为用户十有八九会丢一张 JPG 进来 —— 透明底在 JPG 里会被
压成棋盘格（你那张 `人物立绘.jpg` 就是）。抠图在 `src/main/images.js` 里，全程只用
Electron 自带的 `nativeImage`，不引入任何原生依赖：`toBitmap()` 拿 BGRA 原始像素，
改完再用 `createFromBitmap().toPNG()` 编码回去，1437×1920 的图约 150ms。
已经是透明 PNG 的图会被识别出来直接使用，不再抠第二遍。
界面上有个「不抠图、原样使用」的开关，遇到抠坏的图可以关掉。

**背景图比例和窗口不一致时**，用 `cover` 铺满并裁切，设置里给了横/纵两个滑块微调位置。
窗口固定 1280×713，比例接近的图（比如 1920×1073 的 `替换图1`）几乎不会被裁到。

## 发布新版本

应用内置自动更新，走的 GitHub Releases（仓库 `kiyukoso/tsumugi-reminder`，**必须公开** ——
私有仓库要把访问 token 打进客户端，而客户端在别人手里，等于交出仓库权限）。

发一版：

```bash
npm version patch        # 或 minor / major，会自动提交并打 tag
git push --follow-tags
npm run release          # 打包并上传到 GitHub Releases
```

`npm run release` = `electron-builder` 构建 + `tools/release.js` 用 `gh` 上传，
所以先 `gh auth login` 装好凭据（token 需要 `repo` 权限）。

**这台机器上构建/上传必须加 `NODE_OPTIONS=--use-system-ca`：**

```bash
export NODE_OPTIONS=--use-system-ca
```

不加的话上传会以 `unable to verify the first certificate` 失败。原因是本机有东西
做了 TLS 中间人（多半是杀毒或网络层），它的根证书装在 Windows 证书store 里，
但不在 Node 自带的 CA 列表里。`--use-system-ca` 让 Node 改用系统证书store。
注意 `gh` 本身不受影响（它是 Go 写的，走系统证书），所以会出现
「`gh` 能登录、electron-builder 传不上去」这种看着很矛盾的现场。

### 为什么不用 electron-builder 自带的 `--publish`

`npm run release` 里的 `--publish never` 是**必须的**，两个原因：

1. 它默认建**草稿**，而草稿对 electron-updater 不可见 —— 客户端永远发现不了新版本，
   且不会有任何报错。
2. 它会并发跑多条发布流水线，每条各自判断「release 不存在」然后各建一个。实测生成了
   两个同标签 `v1.0.0` 的草稿，资源还被拆开：一个只有 `latest.yml` 和安装包，另一个
   只有 blockmap。这样的 release 客户端拼不出完整下载地址。

所以改成 `tools/release.js` 直接调 `gh`，一次一条、确定性的，并且显式不加 `--draft`。

另外 electron-builder 的默认发布策略是「在打了 tag 的提交上自动发布」，
`npm version` 会顺手打 tag，所以不加 `--publish never` 它就会自己动起来。

### `latest.yml` 的版本必须和 `package.json` 一致

`tools/release.js` 会在上传前检查这一点，不一致直接拒绝。这是踩过的坑：
自动发布失败时 electron-builder **不会**重新生成这个清单，于是 `dist/` 里留下上一版的
`latest.yml`。带着它上传的话，客户端拿到的"最新版本"还是旧的，更新永远不会发生 ——
而且完全静默，没有任何报错。

客户端的行为：启动 8 秒后静默查一次，发现新版本就后台下载；下完在设置齿轮上点一个小圆点，
打开设置会看到「重启并安装」。用户直接退出应用的话，退出时也会自动装上。

**产物名必须保持 ASCII，而且 `artifactName` 要写在 `build` 顶层。** 这两条都踩过：

- 写在 `nsis` 下面时，`latest.yml`（更新清单）不会采纳它，清单里写的还是默认名
  （`reminder-setup-1.0.0.exe`），而磁盘上生成的是配置里那个名字 —— 清单和实际产物对不上，
  自动更新会去下载一个不存在的文件，而且是**静默失败**。
- 名字里带中文会让更新 URL 变成百分号编码。这个项目里中文已经连着出过三次问题
  （PowerShell 按 GBK 读源码、bash 传中文参数给 PowerShell、中文文件名进 asar），
  更新链路是最不该再赌一次的地方。

另外 `package.json` 里**不能写 `"// xxx"` 这种注释键**，electron-builder 会做 schema 校验，
遇到未知属性直接拒绝构建。

## 背景音乐

进入主界面时开始播放，可以一次添加多首。三种模式：单曲循环 / 顺序播放 / 随机播放。
主界面有一条「正在播放」控制条，桌宠右键菜单里也有同一套控制（不用把主界面翻出来）。

音乐**复制**进 `%APPDATA%\Reminder\music\`，和提示音、自定义图片一致。这里复制比图片
那边更值：歌单是长期攒起来的，而人整理音乐目录是常态 —— 移动文件夹、改文件名、
把歌从 U 盘挪到硬盘，只记路径的话整个歌单会一夜之间变成一串点不动的条目。

支持 mp3 / flac / wav / m4a / aac / ogg / opus，**不支持 mid / wma / ape / dsf**：
mid 是乐谱指令不是音频，需要合成器才能发声；其余几个 Chromium 没有解码器。

播放走 `<audio>` + blob URL，不是 `decodeAudioData` —— 后者会把整首歌解成未压缩
PCM 常驻内存，一首 10MB 的 mp3 能膨胀到几十 MB。

歌单、当前曲目、播放模式都由**主进程**持有，因为桌宠的右键菜单是在主进程里构建的，
它得能直接读状态、直接发指令。渲染进程只负责那个 `<audio>`，并如实回报真实播放状态
（用户点暂停、歌放完、解码失败都要反映过来，否则菜单上的「播放/暂停」会显示错）。

设置里有「藏到托盘或桌宠后暂停播放」的开关，默认关（即继续播）。这个信号由主进程
**显式**发给渲染进程，而不是赌 `visibilitychange` —— Electron 隐藏窗口时页面可见性
未必跟着变，音乐「隐藏暂停」会静默失灵。

## 全屏

右上角有全屏按钮，`F11` 切换、`Esc` 退出。

窗口原来是写死 1280×713、不可缩放的，直接开全屏会让右栏孤零零贴在屏幕右边。
现在右栏宽度封顶 604px、边距按视口比例伸缩（`clamp(380px, 47vw, 604px)`），
所以 1280 宽的默认窗口和 2560 宽的全屏下都是合适的宽度。

**注意背景图的分辨率**：1280×713 的图铺满 2560×1600 要放大 2.25 倍，会明显发糊。
这是分辨率硬限制，改代码解决不了 —— 想要全屏好看得换高分辨率的背景图（设置里能换）。

## 几个值得记一笔的实现决定

**调度只跑一个 250ms 心跳，每次用壁钟比大小**，不用 `setTimeout` 累加计时。
后者在系统休眠或用户改系统时间之后会漂移甚至整段漏掉；壁钟比较则能在
唤醒后的下一拍立刻算出「早就该响了」。

**浮层的可见性靠基准样式，不靠动画的 `fill-mode`。** 用 `both` 的话，
元素可见与否就完全押在动画能正常跑完上，动画一旦被打断就会永久停在
`opacity: 0`——可它同时还是 `display: flex`，于是看不见却照吞点击。
现在的写法是「失败可见」。

**提示音是复制进 `sounds\` 而不是记原路径**。否则用户把源文件删了或挪个
位置，提醒就变成哑巴，而且是在最需要它响的那一刻才发现。

**桌宠窗口比立绘本身宽一圈、高出一截**，多出来的是留给提醒气泡的透明区域，
否则气泡会糊在角色脸上。因为做了逐像素点击穿透，这些空白不会挡住底下窗口。

**逐像素点击穿透**：把立绘缩到 1/4 画进离屏 canvas 取 alpha 表，鼠标移动时
查表，落在透明处就把窗口设为穿透。穿透时用 `forward: true`，否则鼠标滑出去
就再也收不回来，桌宠会永久失去交互。

**抠图的判定核心不是色差，而是「中性色背景只跟中性色像素匹配」。** 用 RGB
欧氏距离直接比会翻车：棋盘格含一个灰 (237,237,237)，而浅蓝裙摆是 (230,235,250)，
两者只差 15，裙子、白领、浅肤色会被整块吃掉。`tools/cutout.js` 里写死的
「必须接近中性灰」正是这个道理，泛化时把它丢掉过一次，代价是角色的腿和手消失。

**背景调色板要求颜色至少「站得住」两条边。** 只按占比筛会出事：`人物立绘.jpg`
的右边缘整列偏暗 (135,134,134)，占比 28% 过了门槛，而它的亮度窗口正好套住裙子
上的褶皱阴影，整条裙子被啃成透明的洞。另外「出现在某条边上」要按长度算 ——
那张图在左上/右下还各有一个孤立角像素，按「有没有」计数就是 3 条边，照样蒙混过关。

**抠图只保留「够大的」连通块，而不是「最大的」那一块。** 角色的腿和飘起来的
裙摆在腐蚀之后可能和主体并不连通，只留最大块会把它们整个删掉。

**桌宠窗口不能建成 `resizable: false`。** Windows 会把不可调整大小的窗口按
**当前尺寸**锁住最大/最小跟踪尺寸，于是 `setSize` 只能把它改大、改不小 ——
实测设 700→300→900→460 这一串里，只有 700 和 900 生效，窗口永久停在最大的
那个尺寸上，表现是「桌宠一旦被改大就再也缩不回去，立绘跟着变大且松手也不恢复」。
现在是始终 `resizable: true`（`setSize` 双向有效），用 `will-resize` 事件把
用户拖边缘拦掉。

顺带记一笔失败的尝试：`setResizable(true) → setSize → setResizable(false)`
挤在同一个 tick 里**不行**，第二次切换会把尺寸改动整个吞掉，比原来还糟（完全改不动）。

另外桌宠窗口有一道**尺寸自愈**：发现尺寸偏离预期就改回去，并写进
`%APPDATA%\reminder\pet-resize.log`。加它是因为遇到过窗口被外部改成
1026×942（预期 300×552）并保持不放，而那个尺寸不是本项目任何公式能算出来的。
容差是 2px —— Windows 会按 DPI 缩放四舍五入窗口尺寸（313 DIP 在 150% 下是
469.5 物理像素，取整回来变 314），不容差会把正常舍入当成外部干预，
而且因为设 313 又被舍回 314，会变成改不完的死循环。

## 开发工具

| 工具 | 用途 |
|---|---|
| `tools/cutout.js` | 重新处理内置素材，生成 `pet.png` / `tray.png` / `icon.ico` |
| `src/main/images.js` | 运行时的图片导入与抠图（用户换图走这里，不是上面的脚本） |
| `tools/_selftest.js` | 单元测试，覆盖调度状态机、持久化、提示音文件处理 |
| `tools/_drive.js` | 通过 CDP 驱动界面：点按钮、查状态、截图 |
| `tools/_shot.ps1` | 截窗口，用于抓桌宠的透明效果（CDP 截图看不清透明） |
| `tools/_windiag.ps1` | 列出所有可见窗口及其进程名和尺寸，截错窗口时用来排查 |

`_drive.js` 需要应用带 `--remote-debugging-port=9222` 启动（用 `npm run dev`）：



```bash
node tools/_drive.js list
node tools/_drive.js index "document.getElementById('btnSettings').click()"
node tools/_drive.js shot index out.png    # 不受遮挡、不会拿到旧帧
```

> 注意：`_shot.ps1` 里刻意**不用** `SetForegroundWindow`。激活 Chromium 窗口
> 会让它在光标位置投递一次合成点击，把光标底下的按钮真的按下去 —— 调试时
> 它就这样点掉过一个「完成」按钮，看起来特别像应用自己的 bug。

`_shot.ps1` 是按**精确像素尺寸**选窗口的，因为进程名过滤有两个坑：打包版的
进程名不是 `electron.exe`（现在是 `tsumugi-reminder.exe`），而中文参数从 bash 传进 Windows
PowerShell 会按 GBK 解析成乱码。拿到窗口后若要传给 `-Proc`，用 `"*"` 即可。

另外这些 `.ps1` **必须保持纯 ASCII** —— 这台机器上 PowerShell 会把非 ASCII
源码按 GBK 解读，中文字符串会直接把语法解析搞崩。

## 关于素材

代码是 MIT 的，但 `assets/` 下那几张动漫背景图和立绘**不在这个许可范围内**，
也不是本项目的原创素材，只是使用者自备的界面配图。它们随仓库公开只是为了
让这个应用能直接跑起来。如果你的使用场景对素材来源有要求，请自行替换成
有授权的图片 —— 设置界面里可以直接换，不用改代码。
